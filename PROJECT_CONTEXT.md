# Контекст проекта Time To Go Backend

## Назначение

`time-to-go-backend` — REST API для приложения Time To Go. Проект помогает участникам евангелизационной работы вести личный учёт людей, с которыми они познакомились, выбранных методов евангелизации, результатов выхода и свидетельств. API также отдаёт общую статистику, данные для карты и публичной ленты свидетельств.

Стек: Python 3.13+, FastAPI, асинхронный SQLAlchemy 2, Alembic, Pydantic 2, JWT (`python-jose`), bcrypt/passlib и Uvicorn. По умолчанию используется SQLite через `aiosqlite`; поддерживается PostgreSQL через `asyncpg` и переменную `DATABASE_URL`.

```bash
uv sync
uv run alembic upgrade head
uv run uvicorn src.main:app --reload
```

Локальный API доступен на `http://127.0.0.1:8000`, интерактивная документация — на `/docs`.

Переменные окружения:

| Переменная         | Назначение                    | Значение по умолчанию                  |
| ------------------ | ----------------------------- | -------------------------------------- |
| `DATABASE_URL`     | Строка подключения SQLAlchemy | `sqlite+aiosqlite:///./app.db`         |
| `SECRET_KEY`       | Ключ подписи JWT              | небезопасный `change-me-in-production` |
| `ADMIN_SECRET_KEY` | Задаётся в Docker Compose     | В коде не используется                 |

Access token подписывается HS256 и действует 7 дней. Для защищённых ручек передаётся заголовок `Authorization: Bearer <access_token>`.

## Архитектура

Точка входа — `src/main.py`: она создаёт FastAPI-приложение, включает CORS для любых origin, публикует каталог `uploads` по пути `/uploads` и регистрирует роутеры.

```text
Клиент
  └─ FastAPI (src/main.py)
      ├─ /auth                 аутентификация и профиль
      ├─ /methods              методы евангелизации
      ├─ /believers            люди, карта, свидетельства
      └─ /outreach-statistics  числовая статистика выходов
            └─ Async SQLAlchemy → SQLite / PostgreSQL
```

Код организован по предметным областям. В каждой из них используются SQLAlchemy-модели (`models`), Pydantic-схемы (`schema`) и роутеры. Общая работа с БД находится в `src/db/session.py`; миграции схемы — в `alembic/versions`.

## Предметная модель

| Сущность             | Суть и связи                                                                                                                                                                    |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `User`               | Аккаунт с именем, email, хешем пароля, профилем и аватаром. Владеет новообращёнными, пользовательскими методами и одной строкой статистики.                                     |
| `Believer`           | Человек, с которым встретились: имя, необязательные Telegram/телефон, дата встречи, духовный этап, заметка, свидетельство, координаты и метод. Принадлежит одному пользователю. |
| `EvangelismMethod`   | Метод евангелизации. Есть глобальные методы по умолчанию и личные методы пользователя.                                                                                          |
| `OutreachStatistics` | Одна агрегированная запись на пользователя: рассказанные Евангелия, молитвы о спасении людей без контакта, розданные Писания/«Отцовские письма», исцеления и освобождения.      |
| `Testimony`          | Отдельное текстовое свидетельство, привязанное к агрегированной статистике пользователя.                                                                                        |

Этапы `Believer.stage`: `interested`, `receivedJesus`, `joinedCommunity`, `baptised`, `evangelist`. Во всех суммарных показателях «спасён» — это любой этап, кроме `interested`.

При создании базы первая миграция добавляет два глобальных метода: «4 знака» и «Иисус у двери». Личный метод виден только его владельцу, глобальный — всем пользователям.

## API по разделам

### Аутентификация и профиль — `/auth`

| Метод и путь                                  | Авторизация | Назначение                                              |
| --------------------------------------------- | ----------- | ------------------------------------------------------- |
| `POST /register`                              | нет         | Регистрация по `name`, `email`, `password`.             |
| `POST /login`                                 | нет         | Вход и получение JWT.                                   |
| `POST /refresh`                               | нет         | Выпуск нового JWT по действующему token в теле запроса. |
| `GET /me`                                     | да          | Текущий профиль.                                        |
| `PATCH /me`                                   | да          | Изменение `name` и/или `about`.                         |
| `POST /me/avatar`                             | да          | Загрузка аватара в поле multipart `avatar`.             |
| `DELETE /me`                                  | да          | Удаление своего аккаунта и зависимых данных.            |
| `GET /all-users`                              | нет         | Список всех аккаунтов.                                  |
| `DELETE /by-email?email=...`                  | нет         | Удаление аккаунта по email.                             |
| `PUT /me/password?email=...&new_password=...` | нет         | Смена пароля по email.                                  |

Аватар сохраняется в `uploads/avatars`, доступен публично через `/uploads/avatars/...`; разрешены JPEG, PNG, WEBP, GIF, HEIC и HEIF размером до 5 МБ.

### Методы — `/methods`

| Метод и путь              | Авторизация | Назначение                                                                      |
| ------------------------- | ----------- | ------------------------------------------------------------------------------- |
| `GET /methods`            | да          | Глобальные и собственные методы текущего пользователя.                          |
| `POST /methods`           | да          | Создание личного метода (`name`).                                               |
| `GET /methods/statistics` | нет         | Количество записей `Believer` по методам «4 знака», «Иисус у двери» и «другой». |

### Новообращённые, карта и свидетельства — `/believers`

| Метод и путь                                     | Авторизация | Назначение                                                                                    |
| ------------------------------------------------ | ----------- | --------------------------------------------------------------------------------------------- |
| `POST /believers`                                | да          | Создание записи. Обязательны имя, дата встречи, этап, ID доступного метода, широта и долгота. |
| `GET /believers`, `GET /believers/my`            | да          | Собственные записи, новые сверху. Это функционально дублирующие маршруты.                     |
| `GET /believers/{id}`                            | да          | Собственная запись по ID.                                                                     |
| `PATCH /believers/{id}`                          | да          | Изменение собственной записи.                                                                 |
| `DELETE /believers/{id}`                         | да          | Удаление собственной записи.                                                                  |
| `GET /believers/all`                             | нет         | Все записи со сведениями о владельце — источник данных для общей карты/ленты.                 |
| `GET /believers/latest`                          | нет         | До 20 последних записей; поддерживает `date_from` и `date_to`.                                |
| `GET /believers/stats/accepted-jesus-count`      | нет         | Общее число людей, чей этап не `interested`.                                                  |
| `GET /believers/testimonies`                     | нет         | Общий список свидетельств от людей и из статистики.                                           |
| `GET /believers/testimony-of-day?day=YYYY-MM-DD` | нет         | Детерминированно выбирает одно свидетельство на указанную дату, либо на сегодня.              |

### Статистика выходов — `/outreach-statistics`

| Метод и путь                          | Авторизация         | Назначение                                                                                            |
| ------------------------------------- | ------------------- | ----------------------------------------------------------------------------------------------------- |
| `GET /summary?type=general\|personal` | для `personal` — да | Итог по всем пользователям или по текущему. Суммирует записи `Believer` и ручные счётчики.            |
| `GET /me`                             | да                  | Личная статистика; при первом обращении создаёт нулевую запись.                                       |
| `POST /add`                           | да                  | Прибавляет неотрицательные значения к счётчикам; может создать свидетельство.                         |
| `PATCH /me`                           | да                  | Устанавливает переданные значения счётчиков; может удалить свидетельство через `delete_testimony_id`. |
| `POST /reset`                         | да                  | Обнуляет пять счётчиков, не удаляя свидетельства.                                                     |
| `GET /all`                            | нет                 | Вся статистика с профилем пользователя и свидетельствами.                                             |

Формулы `summary`:

- `total_heard_gospel` = число `Believer` + `gospels_told`;
- `total_saved` = число `Believer` со стадией не `interested` + `salvation_prayed_unreachable`;
- `contacts_taken` = число `Believer` с Telegram или телефоном;
- остальные показатели — суммы соответствующих ручных счётчиков.

## Данные и миграции

Текущая вершина миграций — `0009_add_fathers_letters_distributed`. Миграции обязательны при развёртывании; `init_db()` в коде существует, но приложением не вызывается. В Docker перед запуском Uvicorn выполняется `alembic upgrade head`.

Для локальной разработки база по умолчанию создаётся как `app.db` в корне репозитория. В Docker Compose применяется SQLite-файл `data/app.db`, а каталог `uploads` монтируется отдельно для сохранения аватаров между перезапусками.

## Развёртывание

Есть `Dockerfile` на основе `ghcr.io/astral-sh/uv:python3.13-bookworm-slim` и `docker-compose.yml` с сервисами `api` и `caddy`. API внутри сети слушает порт 8000. Caddy проксирует HTTP на `:80`; второй listener настроен на `:2015` c сертификатами из `/etc/letsencrypt`.

README заявляет production HTTPS на `api.time.to.go.xn--80a6ad.space` и порт 443, но фактический `docker-compose.yml` не публикует `443`, а `Caddyfile` не содержит host-адреса для автоматического TLS. Перед production-развёртыванием эту конфигурацию нужно сверить и исправить.

## Важные особенности и технический долг

- «Admin» в названиях `GET /auth/all-users` и `DELETE /auth/by-email` не реализован: обе ручки публичны. Также публична смена пароля `PUT /auth/me/password` по произвольному email. Это критическая проблема авторизации.
- `SECRET_KEY` имеет небезопасное значение по умолчанию, поэтому в любом окружении кроме локальной разработки ключ должен быть задан явно и храниться вне репозитория.
- CORS разрешает все origin, методы и заголовки, включая credentials. Для production следует ограничить разрешённые клиентские домены.
- Публичные ручки `/believers/all`, `/believers/latest`, `/outreach-statistics/all` и свидетельства раскрывают данные пользователей и потенциально контактные данные новообращённых. Нужна явная политика доступа и минимизация выдаваемых персональных данных.
- Проверка типа аватара опирается на `Content-Type` или расширение файла, а не на анализ содержимого. При публикации загрузок стоит добавить валидацию файла и безопасную обработку изображений.
- Файлы `src/map/*`, `src/settings/*` и `src/believers/handler.py` сейчас пустые и не подключены. Тестов и CI-конфигурации в репозитории нет.

## Ориентиры для дальнейшей разработки

- Добавлять изменения БД новой миграцией Alembic, а не правкой применённых миграций.
- Сохранять асинхронный путь работы с БД: `AsyncSession`, `select`, `await db.commit()`.
- Новые защищённые эндпоинты подключать через `get_current_user`; отдельную роль/зависимость администратора нужно реализовать до появления реальных админ-операций.
- Документацию OpenAPI FastAPI можно использовать как актуальный контракт форматов запросов и ответов: `/docs` после запуска приложения.
